# 학생 화면 문자열 — 검증 메타데이터 분리 원칙

- `sourceId`, `verified`, "원문 대조 전", "교사 검수 전", "미확인", "[2차]" 같은 라벨은 작업 중 사실 확인을 추적하는 **내부 장치**다.
  학생 화면 렌더링 코드(HTML/JS 문자열)에 배지·토글 라벨·괄호 메모 등 **어떤 형태로도** 넣지 않는다. 검증 상태는 핸드오프 문서·README·커밋 메시지에만.
- 화면 코드가 검증 플래그를 **아예 참조하지 않는다** — 플래그를 읽어 조건부로 뭔가 보여주는 함수를 만드는 순간이 위반 신호.
- `verified:false` 내용은 (a) 검증 후 반영 (b) 검증 전까지 교과서 수준 대체 서술 (c) 아예 뺀다 — 셋 중 하나만.
  "이 내용은 아직 확인 못 했어" 같은 미검증 고지 문장을 학생에게 노출하지 않는다.
- "사료와 해석 분리"는 라벨이 아니라 **화면 구성(카드 순서·카드 분리)** 으로 한다. "이건 해석이야, 사실과 구분해서 읽자" 같은
  학생 대상 설명 문장은 역할극 프레임을 깨므로 넣지 않는다.
- 작업 순서: (1) 콘텐츠·검증 확정 → (2) 검증 상태 정리는 핸드오프 문서 안에서 완료 → (3) 화면 코드는 검증 플래그 미참조.
- **완료 기준**: 학생 화면 렌더링 문자열에서 "검수", "대조", "미확인", "2차", "확인 전"이 0건(grep). 단 기존 피드백 읽음 배지의
  "미확인"은 무관한 정상 텍스트다 — Stop 훅 `check_verification_leak.sh`는 그래서 HEAD 대비 **증가분**만 경고한다.
- 같은 이유로 AI 작성 의심·평소 대비·교차 확인·이탈/붙여넣기 신호, 학급 공통 피드백 "오개념"도 학생 화면 금지(예외: 이탈 기록은
  "선생님이 볼 수 있어요" 배너로 학생에게 숨기지 않고 알린다 — features.md "작성 과정 신호").
