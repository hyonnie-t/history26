# 바이브 테스트 심판 기준

너는 심판이다. 같은 요청으로 만든 앱 두세 개(X·Y·Z, 어느 규칙 판인지 모른다)를 비교한다.
기계 점검(`check.mjs`) 결과는 따로 집계하니 여기서는 **기계가 못 보는 것만** 본다. 코드는 고치지 않는다.

## 점수 (항목마다 0~4, 합계 20)

| 항목 | 4점 | 0점 |
|---|---|---|
| 1. 학생 말 | 선생님이 교실에서 그대로 말할 문장. 설계 용어·번역투 없음 | «전제», «나란히 놓아 봐», «깔고 있는 생각» 같은 말이 여럿 |
| 2. 정답 감추기 | 예시·placeholder·힌트가 정답을 떠올리게 하지 않음. 학생 판단 → 사실 확인 순서 | 예시가 바로 다음 정답을 알려 줌, 정답이 먼저 보임 |
| 3. 직접 풀 수 있음 | 중2 보통 학생이 되어 모든 선택지를 풀어 보면 칸마다 쓸 말이 화면 안에 있음 | 배경지식 없이는 못 품, 옮겨 쓰기만 하게 됨 |
| 4. 태블릿 화면 | 375·768·1180 그림에서 가로 스크롤 없음, 가로 모드에서 자료와 쓰는 칸이 같이 보임(쓰기 활동이면), 버튼이 손가락 크기 | 가로 스크롤, 버튼이 가려짐, 글자가 작음 |
| 5. 틀·조각 따름 | 기존 앱 틀의 뼈대와 조각 설명서의 구조를 따르고, 바꾼 곳은 이유가 보임 | 이미 있는 조각(마무리 화면, 힌트 토글 등)을 새로 짜서 동작이 다름 |

5번은 조각 설명서를 받은 판에만 유리하다. 그래서 점수는 **1~4번 합(16점)**과 **5번 포함 합(20점)**을 따로 적고, 판끼리 비교는 1~4번 합으로 한다. 5번은 «설명서를 실제로 따랐나»를 보는 참고 점수다.

## 적는 법

- 요청마다 X·Y·Z 각각 다섯 점수와 근거 한 줄(파일·위치나 그림 번호).
- 직접 화면에서 눌러 본 것과 코드만 읽은 것을 구분해 적는다(«눌러 봄 / 읽기만»).
- 마지막에 «가장 큰 차이 하나»를 한 줄로. 차이가 없으면 없다고 쓴다.
- 자기 취향(색, 글꼴)으로 점수를 바꾸지 않는다. 배색은 기계 점검과 효니가 본다.
